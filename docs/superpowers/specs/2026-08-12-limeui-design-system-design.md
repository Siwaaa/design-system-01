# limeui — дизайн-система в стиле klipni.com

Дата: 2026-08-12

## Контекст

Реестр `@linkz` (shadcn registry) был вычищен до голого каркаса (только тема + build-тулинг, без компонентов) в этой же сессии. Следующий шаг — построить на этом каркасе новую дизайн-систему `@limeui`, полностью повторяющую визуальный стиль `app.klipni.com` (страница входа + залогиненный дашборд/профиль), чтобы использовать её во всех личных проектах.

Стиль снят не «на глаз», а через `chrome-devtools-mcp`: реальная навигация по живому сайту (включая логин с учётными данными, предоставленными пользователем, чтобы увидеть дашборд/профиль), `getComputedStyle` и canvas-семплинг цветов из `lab()`/`oklab()` в точный sRGB hex.

## Токены темы

| `--foreground` | `#0c0c0b` | body/text color на klipni |

### Цвет (dark)

Полноценная `.dark` тема экстраполируется по той же логике инверсии, что использовалась в старой `linkz`-теме (не буквальный invert, а согласованные по контрасту пары): `background #0c0c0b` / `foreground #f7f7f5`, поверхности (`card`, `secondary`, `muted`) светлеют пропорционально текущей темноте, `--primary` (лайм) остаётся тем же — акцентные цвета в брендинге обычно не переворачиваются между темами.

### Радиус — главная отличительная черта стиля

Нельзя выразить одной линейной шкалой (как было в `linkz`: `sm/md/lg/xl` через множители от одного `--radius`). У klipni кнопки/бейджи/табы всегда pill независимо от размера, а карточки — фиксированные 20px независимо от контента. Именованные токены:

```
--radius-pill: 999px;   /* все интерактивные контролы: button, badge, chip, tabs, avatar */
--radius-lg:   20px;    /* card, основные input */
--radius-md:   14px;    /* textarea, вложенные поверхности */
--radius-sm:   10px;    /* мелкие элементы навигации */
```

### Elevation и motion

- `box-shadow: none` в состоянии покоя — везде, без исключений.
- Только у primary-кнопки: `hover:-translate-y-px`, `hover:shadow-[0_8px_20px_-8px_rgb(12_12_11_/_0.22)]`, `active:scale-[0.97]`, `transition duration-150 ease-out`.

### Типографика

Geist (уже установлен в проекте — совпадение с текущим стеком). Веса только 400/500/600, без light/italic. Отрицательный tracking, увеличивающийся по модулю с размером текста (крупные заголовки — самый тугой трекинг). У uppercase мелких лейблов трекинг **положительный** (инверсия обычного правила) — наблюдалось на лейблах секций сайдбара и на бейджах.

## Компоненты

### Базовые 17 (перенос из `linkz`, рестайлинг)

`alert`, `badge`, `button`, `card`, `checkbox`, `dialog`, `dropdown-menu`, `input`, `label`, `select`, `separator`, `skeleton`, `switch`, `table`, `tabs`, `textarea`, `tooltip`

Ключевые изменения вариантов:
- **Button**: `default` = pill + лайм-фон + hover-lift/active-scale. `secondary` = pill на `bg-soft` (вид OAuth-кнопок). `outline`/`ghost`/`destructive` сохраняют семантику shadcn, но с pill-радиусом.
- **Badge**: `default` = сплошной тёмный pill (статусы вроде «АКТИВНА»), новый `success` вариант = мягкий зелёный pill, `secondary` = мягкий серый pill.
- **Card**: радиус 20px, без тени, тонкая нейтральная граница. Тонированные состояния (как лайм-tint активной кампании) — через `className` у потребителя, не хардкодится вариантом.
- **Input/Textarea**: заливка `bg-soft`, почти невидимая граница в покое, фокус — только тёмное `ring`, без glow.
- **Tabs**: остаётся обычным shadcn-переключателем панелей (underline/box), БЕЗ pill-стилизации — за pill-вид отвечает отдельный компонент ниже.

### Область НЕ входит в реестр

Sidebar-навигация, campaign-card с картинкой, тёмный hero/promo-блок — это композиции уровня страницы конкретного продукта Klipni, не переиспользуемые примитивы. Сборка из Card/Stat/Chip остаётся на стороне потребителя.

### 3 новых компонента (только в `@limeui`, аналогов в дефолтном shadcn нет)

- **`SegmentedControl`** — Radix `RadioGroup`, стилизованный как pill-переключатель «Я креатор / Я бренд»: обёртка `bg-soft` pill с паддингом 6px, выбранный вариант — тёмный pill-индикатор.
- **`Chip`** — переключаемая pill-кнопка (тег/фильтр): выбран = тёмный фон/белый текст, не выбран = `bg-soft`. Покрывает и tag-select в профиле («Клиппинг», «UGC»), и фильтр-строку кампаний («Все», «UGC», «Нарезки»…).
- **`Stat`** — лейбл (uppercase, разрежённый трекинг, приглушённый цвет) + крупное жирное число, для баланс/стат-плиток.

## Механика реестра и сборки

- `registry/limeui/theme/theme.css` и `registry/limeui/ui/*.tsx` — уже существуют как пустой каркас с прошлой сессии, наполняются.
- `registry.json` (корень): `name` → `limeui`, 17 базовых items + 3 новых (`segmented-control`, `chip`, `stat`), у каждого `registryDependencies: ["@limeui/theme"]`.
- Пустая директория `registry/linkz/` удаляется.
- `scripts/build-registry.mjs` — логика не меняется, путь к theme.css переключается на `registry/limeui/theme/theme.css`.
- `r/` — пересобирается через `pnpm build:registry`, коммитится вместе с исходниками.
- `CLAUDE.md` и `README.md` — переписываются под `limeui` (имя, палитра, команда `shadcn registry add "@limeui=..."`).
- `src/App.tsx` — демо-страница показывает все 20 компонентов (17 базовых + 3 новых) в light/dark, тумблер темы уже есть в каркасе.

## Проверка

- `pnpm build:registry` — синк темы + сборка `r/` без ошибок.
- `pnpm build` — `tsc -b && vite build` проходит.
- Демо-страница открыта в браузере (`pnpm dev`), визуально сверена со скриншотами klipni.com для ключевых компонентов (кнопка, бейдж, карточка, инпут, chip, segmented control, stat).
- По готовности — Pull Request с итогом работы.
